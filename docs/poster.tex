\begin{block}{Introduction \& Motivation}
Large photo libraries are difficult to search by \textbf{visual content}.
Traditional tools rely on filenames and metadata, requiring manual tagging
that does not scale.

\medskip
\textbf{BEST Cluj-Napoca}, a student organisation, accumulates \textbf{thousands of
event photos} per year across Google Drive. Locating photos of a specific person,
logo, or scene is a slow, manual process.

\medskip
This project builds a \textbf{full-stack semantic photo search engine} that
understands image content using state-of-the-art AI models, without
requiring any manual tagging.
\end{block}

\vskip1.4ex

\begin{block}{Problem Statement}
\begin{itemize}
  \item Keyword search fails for visual content queries
  \item Manual tagging is impractical at the scale of thousands of photos
  \item No unified tool covers semantic, face, and logo search simultaneously
  \item Photos scattered across dozens of Google Drive albums
\end{itemize}
\end{block}

\vskip1.4ex

\begin{block}{Research Objectives}
\begin{enumerate}
  \item Design a scalable microservices backend with Google Drive integration
  \item Implement three AI search modalities: text, face, and logo
  \item Build an intuitive web interface for non-technical users
  \item Enable real-time incremental indexing of new albums
\end{enumerate}
\end{block}

\vskip1.4ex

\medskip
During \textbf{indexing}, each album's images are passed through the relevant AI encoder
and the resulting vectors are stored in a persistent FAISS index on disk.
At \textbf{query time}, only the query is encoded and compared against the pre-built
index, enabling \textbf{sub-second search} across thousands of images.

\begin{column}{0.28\linewidth}

\begin{block}{Search Modalities}

\textbf{\textcolor{brandpurple}{1 \ Text Search}}\\
Users describe a scene in natural language (e.g.\ \textit{"people on a boat at sunset"}).
CLIP maps both the text and all indexed photos into a shared embedding space;
FAISS retrieves the $k$ most similar images in milliseconds.

\medskip
\textbf{\textcolor{brandpurple}{2 \ Face Search}}\\
Users upload one or more reference photos of a person.
InsightFace extracts face embeddings and returns all indexed photos
containing that individual, regardless of lighting or pose.

\medskip
\textbf{\textcolor{brandpurple}{3 \ Logo / Object Search}}\\
OWL-ViT performs open-vocabulary object detection on reference images,
enabling searches for brand logos, sponsor banners, or visual patterns
without any domain-specific retraining.
\end{block}

\vskip1.4ex

\begin{block}{Implementation Highlights}
\begin{itemize}
  \item \textbf{Microservices:} Auth, Indexing, Search independently deployable
  \item \textbf{Google OAuth2:} role-based access (admin vs.\ viewer)
  \item \textbf{Incremental indexing:} individual albums re-indexable without downtime
  \item \textbf{Persistent FAISS:} indexes survive service restarts via Docker volumes
  \item \textbf{Year-grouped UI:} albums organised by year with collapsible sections
  \item \textbf{Single interface:} text, face, and logo search in one responsive page
\end{itemize}
\end{block}

\vskip1.4ex

\begin{block}{Conclusions}
A fully functional AI-powered photo search system was designed,
implemented, and deployed for real-world use:

\medskip
\begin{itemize}
  \item[$\checkmark$] Three search modalities: semantic, biometric, visual pattern
  \item[$\checkmark$] Microservices architecture with independent scalability
  \item[$\checkmark$] End-to-end Google Drive integration for a real organisation
  \item[$\checkmark$] Responsive web UI accessible to non-technical users
  \item[$\checkmark$] Fully containerised, deployed on Oracle Cloud Always Free
\end{itemize}

\medskip
\textbf{Future work:} automatic album tagging, video clip search, mobile app.
\end{block}
